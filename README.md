# Courtside — Basketball Stats

iPhoneの縦持ちで、自チームのバスケットボール・スタッツを観戦しながら記録するWebアプリです。**スタッツ → 選手**の2タップを基本とし、入力ごとに端末内へ保存します。Basketball Logbookの「スタッツを先に選ぶ」操作思想を参考に、独自の画面を実装しています。

HTML / CSS / Vanilla JavaScript / IndexedDB / Service Worker / Web App Manifestで構成しています。フレームワーク、外部フォント、CDN、アカウント、クラウドDB、バックエンドへの依存はありません。アプリ本体のビルドやnpm installも不要です。

## 起動・ローカル開発

Node.js 20以降で、プロジェクトフォルダから実行します。

```sh
node scripts/serve.mjs
```

[http://127.0.0.1:4173/](http://127.0.0.1:4173/)を開いてください。`npm start`でも同じように起動します。開発用サーバーはファイルを配信するだけで、試合データを受け取りません。

- 初回はオンライン状態で、右上の「オフライン利用OK」を確認します。
- 以降は通信がなくても起動・新規作成・入力・再開・閲覧・編集・集計・JSON入出力・CSV出力ができます。
- HTMLをダブルクリックして`file://`で開く方法では動作しません。ES ModulesとService Workerのため、localhostまたはHTTPSを利用します。
- `PORT`環境変数でポート、`HOST`環境変数で待受アドレスを変更できます。初期値は`127.0.0.1`です。
- iPhoneからPCのLAN IPを**HTTP**で開くだけではService Workerを使用できません。iPhoneでの確認にはHTTPSの静的ホスティングを利用してください。
- 開発時もキャッシュが優先されます。変更確認時は開発者ツールのApplication / Service Workersで「Update on reload」や登録解除を使うか、`sw.js`の`VERSION`を更新し、すべてのアプリ画面を閉じて開き直します。試合データが必要な場合、ブラウザの「サイトデータ全消去」は使わないでください。

## 操作

1. 「チーム」でチーム名、背番号、選手名を登録します。1チーム1〜60人、背番号は1〜3桁で、`0`と`00`も登録できます。
2. 「試合を記録する」で日付、自チーム、対戦相手、ゲーム形式、ピリオド時間、出場メンバーを設定します。チーム・試合作成フォームの入力途中も下書き保存されます。
3. 先発は未設定または5人を選択します。5人設定時は交代管理が有効になります。
4. スタッツをタップし、選手をタップすると記録完了です。保存完了後に入力画面へ戻ります。
5. ホームに戻った場合やアプリを閉じた場合は、「記録中の試合」から再開できます。
6. 試合メニューで終了すると、BOX SCOREと履歴に結果が残ります。終了後も履歴の編集と記録再開が可能です。

### 入力画面

- 2列の大きなボタン：`2P ○ / 2P ×`、`3P ○ / 3P ×`、`FT ○ / FT ×`、`OR / DR`、`AST / STL`、`BLK / TO`、`F / SUB`。
- 成功したシュートから自チーム得点を自動計算します。相手は`+1 / +2 / +3`だけを記録します。
- 画面上にチーム名・スコア・現在ピリオド、下にUNDO・BOX SCORE・直近3件の履歴を表示します。
- 先発設定時の選手選択はコート上の5人が優先です。「ベンチの選手を表示」からベンチ選手のスタッツも記録できます。
- 試合開始後も、試合メニューの「メンバーを追加」から登録済み選手、または新しい選手を追加できます。新しい選手はチームと試合へ同時に保存され、選手選択・BOX SCORE・CSVへ反映されます。登録済み選手は追加時に現在の背番号と名前を変更できます。
- 選手IDは背番号から独立しています。チームで背番号を変更しても過去試合は試合開始時の背番号を保持し、以後の試合はチームの現在の背番号を使います。
- `SUB → OUT → IN`で交代を記録します。出場時間は計測しません。先発未設定の試合では、SUBを押したときに現在コート上の5人を設定してから交代できます。
- UNDOは**最後に追加した、未削除のイベント1件**を取り消します。スタッツ・相手得点・交代に対応します。ピリオド変更、終了操作、編集自体はUNDO対象ではありません。
- 直近イベント、または「履歴・編集」をタップすると、項目・選手・ピリオド・相手得点を修正、個別削除できます。交代選手の修正は削除と再入力で行います。後続の交代が成立しなくなる削除は拒否します。
- 「試合履歴」の各カード右側のゴミ箱から、試合とその全イベントログを削除できます。確認後は復元できないため、必要なら先にJSONバックアップを書き出してください。
- ピリオド名をタップすると、前・次への移動とOT追加を操作できます。移動は確認画面を挟み、過去の入力は変更しません。
- 4Q、2H、任意1〜12ピリオド、1〜60分（0.5分単位）に対応します。時間プリセットは5・6・7・8・10・12分。OTは任意時間（初期5分）で追加できます。通常分とOTの合計上限は50ピリオドです。
- ゲームクロック・カウントダウン・MINは実装しません。

### 連続入力と表示

「設定」の連続入力は**初期OFF**です。ONにすると2P・3P成功後にAST、失敗後にOR / DRを提案します。FTには提案しません。シュートは提案表示前に保存済みなので、「なし」や閉じる操作、アプリ終了でも失われません。ASTではシュートした本人を除外します。

「試合中は画面をスリープさせない」をONにすると、試合画面を表示している間だけScreen Wake Lockを取得します。対応ブラウザでは自動ロックを防ぎ、画面を離れたときや省電力設定では解除されます。初期値はOFFです。

ライト・ダーク・端末設定に連動する外観に対応します。iPhoneのセーフエリアと画面の実際の高さに合わせます。通常の縦画面ではスタッツが1画面に収まります。小さい画面や大きな表示設定で高さが不足する場合は中央のスタッツ部分だけがスクロールし、スコアとUNDOを画面内に保ちます。WebからiPhoneの画面方向を強制できるとは限らないため、縦持ちでの利用を前提とします。

### BOX SCORE

選手別・チーム合計のPTS / REB / AST / STL / BLK / TO / Fを一覧表示します。選手をタップすると、FG・2P・3P・FTの成功数/試投数/成功率、OR・DRを含む全項目を表示します。チームのシュート成績、OR/DR/REB合計、各Q/H/OTの両チーム得点も表示します。試投0の成功率は`—`、それ以外は小数点1桁です。

## GitHub Pagesへの公開

1. GitHubでリポジトリを作成し、このプロジェクトのファイルをpushします。`test-results/`と`node_modules/`は公開不要で、`.gitignore`に登録済みです。
2. リポジトリの **Settings → Pages** を開きます。
3. Sourceで **Deploy from a branch**、対象ブランチ（例：`main`）、フォルダ **/ (root)** を選択して保存します。
4. 配布URL（例：`https://YOUR_NAME.github.io/BB_log/`）を開きます。
5. 「オフライン利用OK」を確認し、一度通信を切って再起動します。

ルート配信だけでなく`/BB_log/`などのサブディレクトリ配信にも対応しています。CSS・JS・アイコン・Manifest・Service Workerは相対URL、画面遷移はハッシュルーティングなので、GitHub Pages用のリライト設定は不要です。`.nojekyll`も含めています。

最小の公開対象：

```text
index.html
css/
js/
icons/
manifest.webmanifest
sw.js
.nojekyll
```

更新時は必ず`sw.js`の`VERSION`を変更してください。キャッシュ名はバージョンと公開スコープで分離します。新バージョンは全アセットのキャッシュ完了後に待機し、旧バージョンの画面がすべて閉じられてから適用します。試合中の強制リロードは行いません。IndexedDBはアプリキャッシュの更新・削除とは独立しています。

GitHubの設定手順については[GitHub Pagesの公開元設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)も参照してください。

## iPhoneのホーム画面に追加

1. SafariでHTTPSの公開URLを開きます。
2. 共有メニューから「ホーム画面に追加」を選びます。
3. 表示される場合は「Webアプリとして開く」をONにして追加します。
4. 追加されたCourtsideをホーム画面から起動し、「オフライン利用OK」になるまでオンラインで待ちます。
5. 機内モードにして起動と試合再開を確認します。

Safariとホーム画面アプリで保存領域が共有されない環境もあるため、初回キャッシュとデータの確認は**実際に利用するホーム画面アプリ側**で行ってください。必要に応じてSafari側からJSONを書き出して移行します。

[Apple公式：iPhoneのSafariでWebサイトをアプリにする](https://support.apple.com/ja-jp/guide/iphone/iphea86e5236/ios)

## データ保存と整合性

データベース名は`courtside-log`、現在のDBバージョンは1です。IndexedDB操作は`js/db.js`に集約しています。

| ストア | 内容 |
| --- | --- |
| `teams` | チーム名・登録選手・更新リビジョン |
| `games` | 試合情報・ロスターのスナップショット・先発・ピリオド・現在位置・終了状態・連番・リビジョン |
| `events` | スタッツ・相手得点・交代のイベントログ。`gameId`インデックス付き |
| `settings` | 連続入力・画面スリープ防止・外観・作成中の下書き・復元世代 |

イベントの例：

```json
{
  "id": "event-uuid",
  "gameId": "game-uuid",
  "periodId": "period-uuid",
  "eventType": "2PM",
  "playerId": "player-uuid",
  "points": 2,
  "seq": 1,
  "timestamp": "2026-09-05T09:00:00.000Z"
}
```

- 最終スタッツ値は保存せず、未削除イベントから毎回集計します。イベントは時計の前後ではなく試合内の`seq`で順序付けします。
- UNDOと削除は`deletedAt`を付けるソフトデリートです。削除済みイベントもJSONに含めます。編集は同じイベントIDを更新し、`updatedAt`を付けます。編集前の全バージョン履歴は保存しません。
- 交代は`eventType: "SUB"`と`outPlayerId`・`inPlayerId`を保存し、先発と交代ログからコート上の選手を再構築します。
- 選手情報は試合ごとにコピーするので、チームの背番号や名前を後日編集しても過去の試合は変化しません。
- イベントと試合リビジョンを**同一トランザクション**で更新し、完了通知を受け取ってから「保存済み」を表示します。対応環境ではstrict durabilityを要求します。
- 保存中の重複操作を抑止します。保存が失敗するとスコアや履歴に反映せず、エラーと未保存状態を表示し、選手選択を保って再試行できます。
- 同一試合を複数画面で編集した場合はリビジョン不一致を検出し、古い書き込みを拒否します。JSON復元時は世代も更新するため、復元前に開いていた画面からの書き込みも拒否します。
- JSON復元は事前にID・参照先・値・重複・交代整合性を検証し、全ストアを1トランザクションで置き換えます。検証失敗・保存途中の失敗では元のデータを保持します。

端末・ブラウザ・公開URLのオリジンごとの保存です。PCとiPhoneの間で同期はされません。端末故障、ブラウザのサイトデータ削除、保存領域の回収では失われる可能性があるため、定期的なJSONバックアップをご利用ください。保存領域の保持は設定からリクエストできますが、許可はブラウザが判断します。

## バックアップ・復元・共有・CSV

「設定とデータ」から操作します。ファイル操作を含め、オフラインで利用できます。

- **全データを書き出す**：チーム・試合・削除済みを含むイベント・設定・下書きをJSONでダウンロードします。iPhoneではSafariのダウンロードや「ファイル」へ保存してください。
- **JSONから復元**：Courtsideの`schemaVersion: 1`のJSONを読み込みます。上限30MBです。検証後にチーム・試合・記録件数を表示し、「置き換えて復元」で実行します。既存データとのマージではありません。必要な現行データは先に書き出してください。
- **共有画像**：BOX SCORE右上の「共有」で試合全体を、選手詳細の「この選手を画像で共有」で個人スタッツをPNG化します。iPhoneでは共有シートが開き、LINE・メール・AirDrop・写真への保存などを選べます。未対応ブラウザではPNGをダウンロードします。画像生成と共有はオフラインでも利用できます。
- **LINEへ共有**：BOX SCORE右上の「共有」→「LINEへ共有」で、1試合の集計をDeflate圧縮した短い閲覧専用リンクを作ります。LINEには日付・自チーム名・対戦相手名・スコアも本文として渡すため、共有先で内容を確認できます。受信者はリンクをタップするだけでBOX SCOREを開き、選手をタップして詳細を見られます。データはURLのフラグメント（`#`以降）で端末内処理され、GitHub Pagesへ保存されません。旧形式のリンクも引き続き開けます。リンクを知っている人は閲覧できるため、転送先は選んでください。
- **閲覧用共有レポート**：BOX SCORE右上の「共有」から、1試合の集計だけをJSONファイルとして送れます。受信者はCourtsideの「設定」→「共有レポートを開く」で、BOX SCOREとタップ可能な選手詳細を読み取り専用で表示できます。イベントログ・チーム台帳・設定・内部IDは含まず、受信者の保存データにも追加しません。ファイルを送るだけなので、スタッツをサーバーへ公開しません。
- **CSV**：各試合のBOX SCORE右上から、選手全員・チーム合計・ピリオド別得点を出力します。日本語用UTF-8 BOM、CRLF、CSVエスケープと表計算ソフトの数式入力対策を含みます。

試合データをネットワーク送信する処理はありません。HTTP通信はアプリファイルの初回取得と更新確認だけです。

## テスト

単体テストは追加依存なしで実行できます。

```sh
node --test tests/domain.test.mjs
```

ブラウザテストには開発用のPlaywrightが必要です。アプリ本体の依存には含めていません。

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium webkit
node tests/browser.mjs
node tests/resilience.mjs
```

WebKitで操作テストを実行する場合（PowerShell）：

```powershell
$env:BROWSER_ENGINE = 'webkit'
node tests/browser.mjs
```

テストは自分で一時的なローカル配信元とブラウザプロファイルを作ります。通常利用中のブラウザデータは変更しません。スクリーンショット等はGit管理対象外の`test-results/`に保存します。`PLAYWRIGHT_PATH`で既存のPlaywrightパッケージ、`PLAYWRIGHT_BROWSERS_PATH`でインストール済みブラウザの場所を指定できます。

検証範囲：

- 全13項目・シュート率・チーム合計・ピリオド別スコア。
- チーム・試合の下書き復元、2タップ入力、交代、UNDO、イベント編集、AST/REB連続入力。
- 390×844 / 375×667 / 320×568で横スクロールがなく、44px以上のスタッツボタンと画面内のUNDO。
- IndexedDB書き込み失敗で集計に反映されないこと、複数画面での競合検出。
- オフライン再読込・新規試合・BOX SCORE・CSV・JSONの書き出し/復元。
- ブラウザを完全終了してからオフラインで再起動し、試合を再開。
- 復元途中の失敗で元データが残ること、復元後の古い画面からの書き込み拒否。
- GitHub Pages相当のサブディレクトリと、試合中に適用されないService Worker更新。

Windows版Playwright WebKitでは`setOffline(true)`後のナビゲーションがエンジン内部エラーになるため、WebKitのE2Eは配信元を切断し、キャッシュだけで全操作を検証します。Chromiumでは`setOffline(true)`とブラウザ再起動も検証します。**実機iPhone Safari / ホーム画面PWAでの最終確認は別途必要です。** Safariの共有・保存画面やOSによるストレージ管理までデスクトップのエミュレーションでは再現できません。

Service Worker実装の参考：[MDN — Using Service Workers](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)
